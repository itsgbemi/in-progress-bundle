# Security Policy

We take the security of **my-office** seriously. If you believe you have found a security vulnerability, please review the instructions below to report it to us responsibly.

---

## Supported Versions

Only the latest release of **my-office** is actively supported with security updates and patches. Please ensure you are running the most up-to-date version of the software on your workspace.

| Version | Supported |
| ------- | --------- |
| v1.0.x  | ✅ Yes     |
| < v1.0  | ❌ No      |

---

## Reporting a Vulnerability

**Please do not report security vulnerabilities via public GitHub issues, forum posts, or public channels.** 

To report a vulnerability privately, please follow these steps:

1. **Send an Email**: Email your report to [security@my-office.software](mailto:security@my-office.software) (or your designated workspace support email).
2. **Include Key Details**:
- A detailed description of the vulnerability.
- Step-by-step instructions (or a proof-of-concept script/exploit) to reproduce the issue.
- The potential impact of the vulnerability if exploited.
3. **Acknowledgment**: We will acknowledge receipt of your vulnerability report within **48 hours** and provide a status update on remediation efforts.

### Scope

This security policy covers:
- Core frontend components, webpage layout builders, and local caching.
- Server endpoints (`server.ts`) and CMS field-validation controllers.

---

## Disclosure Process

We adhere to coordinated vulnerability disclosure. Once a vulnerability is verified:
1. We will work diligently on a patch to resolve the issue.
2. We will release a minor version or update patch.
3. Users/workspace admins will be notified to pull the update to protect their local systems.
4. We will publicly credit you for the discovery (if desired) after the patch is rolled out.

Thank you for helping keep **my-office** workspaces safe!
